### 1.1 Crate 依赖规则

- `mq-common` 不依赖 tokio/网络/存储。

- `mq-proxy` 依赖 protocol + client（内部转发）；不直接写 store。
- `mq-client` 依赖 protocol；可被 bench 复用。

## 2. 核心数据结构

### 2.1 消息模型

```rust
pub struct Message {
    pub topic: String,
    pub queue_id: i32,
    pub body: Bytes,
    pub properties: HashMap<String, String>,
    pub tags: Option<String>,
    pub keys: Option<String>,
    pub flag: i32,
    pub born_timestamp: i64,
    pub born_host: SocketAddr,
    pub store_timestamp: i64,
    pub store_host: SocketAddr,
    pub reconsume_times: i32,
    pub prepared_transaction_offset: u64,
    pub sys_flag: i32,
}

pub struct MessageId(pub [u8; 16]);
```

### 2.2 CommitLog 记录

```text
+----------------+----------------+----------------+----------------+
| total_size i32 | magic u32      | body_crc u32   | queue_id i32   |
+----------------+----------------+----------------+----------------+
| flag i32       | queue_offset i64 | physical_offset i64            |
+----------------+----------------+----------------+----------------+
| sys_flag i32   | born_ts i64    | born_host(16)  | store_ts i64   |
+----------------+----------------+----------------+----------------+
| store_host(16) | reconsume i32  | prepared_tx_offset i64         |
+----------------+----------------+----------------+----------------+
| body_len i32   | body[body_len] | topic_len u8   | topic[topic_len]|
+----------------+----------------+----------------+----------------+
| prop_len i16   | properties[prop_len]                            |
+-----------------------------------------------------------------+
```

- `total_size` 用于跳过损坏记录。
- `body_crc` 用于恢复校验（可配置）。
- `queue_offset` 在 append 时确定（按 topic/queue 递增）。
- `physical_offset` = 文件起始 offset + 文件内偏移。

### 2.3 ConsumeQueue 条目（20B）

```text
commitlog_offset i64 | msg_size i32 | tag_hash i64
```

- `tag_hash` 用于 Broker 侧快速过滤；SQL92 仍需读属性。
- 每条 20B，按 `queue_offset` 顺序追加。
- 文件大小固定（如 600 万条/文件），mmap 映射。

### 2.4 事务记录

见 `05-事务性设计` 的 `TxRecord`；`mq-txn` 用 `bincode`/自定义二进制 + CRC 写入 WAL，openraft `RaftStorage` 存日志/状态机快照。

## 3. 存储核心算法

### 3.1 CommitLog 追加

```rust
pub struct CommitLog {
    dir: PathBuf,
    files: Vec<MappedFile>,
    active: Arc<MappedFile>,
    append_lock: Mutex<AppendState>,
    flush: FlushHandle,
}

impl CommitLog {
    pub fn append(&self, msg: &Message) -> Result<AppendResult> {
        let mut st = self.append_lock.lock();
        let need_new = st.wrote + msg.encoded_len() > self.file_size;
        if need_new {
            self.roll_new_file(&mut st)?;
        }
        let file = self.active.clone();
        let offset_in_file = st.wrote;
        let physical = file.base_offset + offset_in_file as u64;

        // 1. 预留空间，避免半条记录
        file.ensure_capacity(offset_in_file, msg.encoded_len())?;
        // 2. 编码到 mmap（或 writev）
        let n = msg.encode_to(&file.as_mut_slice()[offset_in_file..])?;
        // 3. 更新状态
        st.wrote += n;
        st.last_write_ms = now_ms();
        st.max_physical = physical + n as u64;

        // 4. 刷盘策略
        match self.flush.mode {
            FlushMode::Sync => self.flush.enqueue_sync(physical + n as u64),
            FlushMode::Async => self.flush.mark_dirty(physical + n as u64),
        }
        Ok(AppendResult { physical_offset: physical, wrote: n, queue_offset: msg.queue_offset })
    }
}
```

**关键点**：
- 追加锁只保护“分配 offset + 写 mmap”，不包含 fsync。
- 文件轮转先创建新文件、再切换 active；旧文件引用计数归零后 unmap/删除。
- 写入失败（磁盘满）返回 `SERVICE_NOT_AVAILABLE`/`SYSTEM_ERROR`，并进入只读保护。
- 崩溃恢复扫描最后一个文件，按 `total_size` 跳过不完整尾部。

### 3.2 启动恢复

```text
1. 读取 checkpoint（flush offset / max physical / queue offsets）。
2. 扫描 commitlog 最后若干文件：
   - 校验 magic/total_size/CRC；
   - 遇到不完整记录，截断到上一条完整记录；
   - 重建 max_physical。
3. 对比 consumequeue 的 max offset 与 commitlog：
   - 若 CQ 落后，重放 dispatch；
   - 若 CQ 超前（异常），回滚到 commitlog 可确认的位置。
4. 恢复 topic/queue 元数据、位点、事务日志。
5. 进入服务前完成一次 checkpoint。
```

### 3.3 Dispatch（CommitLog → ConsumeQueue）

```rust
pub async fn dispatch_loop(...) {
    loop {
        let batch = commitlog.read_dispatch_batch(last_pos, 32.MB)?;
        for msg in batch {
            let cq = consumequeue.get_or_create(&msg.topic, msg.queue_id);
            cq.append(msg.queue_offset, msg.physical_offset, msg.size, tag_hash(&msg));
            index.maybe_put(&msg);
        }
        checkpoint.update_dispatch(last_pos);
        if lag > high_watermark { backpressure(); }
    }
}
```

- Dispatch 是异步的；`ConsumeQueue` 可见位点 = `dispatched_offset`。
- 读取时不能超过 `dispatched_offset`，避免读到未建索引的消息。
- Dispatch 失败重试；磁盘满时停止写入/告警。

### 3.4 读取

```rust
pub fn read(&self, topic: &str, queue_id: i32, offset: i64, max: usize) -> Result<Vec<Message>> {
    let cq = self.consumequeue.get(topic, queue_id)?;
    let entries = cq.read(offset, max)?;
    let mut out = Vec::with_capacity(entries.len());
    for e in entries {
        let msg = self.commitlog.read(e.physical_offset, e.size)?;
        if e.tag_hash != 0 && !tag_match(...) { continue; }
        out.push(msg);
    }
    Ok(out)
}
```

- 批量读 CommitLog 时按物理 offset 排序，利用 PageCache 局部性。
- 大消息可分片读取；避免一次性分配过大 buffer。
- 冷读限流：按 topic/consumer 令牌桶。

## 4. Remoting 协议编解码

### 4.1 帧格式

```text
+----------------+----------------+----------------+----------------+
| total_len i32  | header_len i32 | header JSON    | body           |
+----------------+----------------+----------------+----------------+
total_len = 4 + header_len + body_len   // 不包含 total_len 自己的 4 字节
```

### 4.2 Header

```rust
#[derive(Serialize, Deserialize)]
pub struct RemotingCommand {
    pub code: i32,
    pub language: String,      // "JAVA" / "RUST" / ...
    pub version: i32,
    pub opaque: i32,
    pub flag: i32,             // 0 request, 1 response
    pub remark: Option<String>,
    pub ext_fields: Option<HashMap<String, String>>,
    #[serde(skip)]
    pub body: Option<Bytes>,
}
```

**兼容要点**：
- JSON 字段名必须是 `code`、`language`、`version`、`opaque`、`flag`、`remark`、`extFields`。
- `flag` 的 bit0 表示 response；bit1 表示 oneway。
- 请求/响应使用同一 `opaque` 关联。
- 错误响应设置 `remark` + 响应码。
- body 长度由 `total_len - 4 - header_len` 推导。

### 4.3 关键命令码

| 命令 | code | 方向 |
|---|---|---|
| SEND_MESSAGE | 10 | Client → Broker |
| PULL_MESSAGE | 11 | Client → Broker |
| QUERY_CONSUMER_OFFSET | 14 | Client → Broker |
| UPDATE_CONSUMER_OFFSET | 15 | Client → Broker |
| GET_ROUTEINFO_BY_TOPIC | 105 | Client → NameServer |
| REGISTER_BROKER | 103 | Broker → NameServer |
| UNREGISTER_BROKER | 104 | Broker → NameServer |
| HEART_BEAT | 34 | Client/Broker → NameServer |
| END_TRANSACTION | 37 | Client → Broker |
| CHECK_TRANSACTION_STATE | 39 | Broker → Client |
| GET_MAX_OFFSET | 30 | Client → Broker |
| GET_MIN_OFFSET | 31 | Client → Broker |
| SEARCH_OFFSET_BY_TIMESTAMP | 32 | Client → Broker |
| CONSUMER_SEND_MSG_BACK | 36 | Client → Broker |

> 完整表以 4.9.8 `RequestCode`/`ResponseCode` 为准；R1 建立常量表 + golden 测试，禁止魔法数字散落。

### 4.4 发送请求 extFields（示例）

```text
producerGroup, topic, queueId, sysFlag, bornTimestamp, flag,
properties, reconsumeTimes, unitMode, batch, maxReconsumeTimes
```

- `properties` 是 `key\x01value\x02...` 编码（RocketMQ 约定），需与 Java 客户端一致。
- `sysFlag` 包含压缩/事务/顺序等位。
- `batch` 为 true 时 body 是批量编码。

## 5. 发送处理

```rust
pub async fn handle_send(req: RemotingCommand, ctx: &BrokerCtx) -> Result<RemotingCommand> {
    let hdr: SendMessageRequestHeader = req.decode_ext()?;
    let msg = Message::from_request(&hdr, req.body)?;

    ctx.validator.check(&msg)?;                 // topic/queue/body/ACL
    let route = ctx.topic_manager.get_or_create(&msg.topic)?;
    let queue_id = hdr.queue_id.unwrap_or_else(|| route.select_queue(&msg));
    let queue_offset = ctx.store.next_queue_offset(&msg.topic, queue_id);
    let msg = msg.with_queue(queue_id, queue_offset);

    let res = ctx.store.append(&msg)?;
    ctx.metrics.send(msg.topic, res.wrote);

    let status = match res.flush_result {
        FlushResult::Ok => ResponseCode::SUCCESS,
        FlushResult::Timeout => ResponseCode::FLUSH_DISK_TIMEOUT,
        FlushResult::SlaveTimeout => ResponseCode::FLUSH_SLAVE_TIMEOUT,
    };
    RemotingCommand::response(status, SendMessageResponseHeader {
        msg_id: msg.id(),
        queue_id,
        queue_offset,
        transaction_id: hdr.transaction_id,
    })
}
```

**错误码**：
- Topic 不存在：`TOPIC_NOT_EXIST`（或自动创建）。
- 队列满/磁盘满：`SERVICE_NOT_AVAILABLE`/`SYSTEM_ERROR`。
- 消息过大：`MESSAGE_ILLEGAL`。
- 无权限：`NO_PERMISSION`。
- 事务消息发到普通 Topic：`MESSAGE_ILLEGAL`（5.x 语义）。

## 6. 拉取与长轮询

```rust
pub async fn handle_pull(req, ctx) -> Result<RemotingCommand> {
    let hdr: PullMessageRequestHeader = req.decode_ext()?;
    let offset = hdr.queue_offset;
    match ctx.store.read(&hdr.topic, hdr.queue_id, offset, hdr.max_msg_nums)? {
        msgs if !msgs.is_empty() => respond_messages(msgs),
        _ => {
            // 长轮询：挂起直到有新消息/超时
            ctx.long_poll.suspend(hdr.topic, hdr.queue_id, offset, hdr.suspend_timeout_ms).await
        }
    }
}
```

**长轮询实现**：
- 每个 `(topic, queue)` 维护等待队列；消息到达时唤醒。
- 挂起请求有上限（全局 + 按连接），超时返回 `PULL_NOT_FOUND`。
- 客户端断开时取消等待，避免泄漏。
- 与消费位点/过滤条件一起保存，唤醒后重新读取。

## 7. 延时/定时

### 7.1 4.x 18 级延时

- 配置 `messageDelayLevel = "1s 5s 10s 30s 1m 2m 3m 4m 5m 6m 7m 8m 9m 10m 20m 30m 1h 2h"`。
- 消息写入 `SCHEDULE_TOPIC_XXXX` 对应 queue（level-1），到期后由 `ScheduleMessageService` 重新投递到真实 Topic。
- 每个 level 一个定时器 + offset；持久化进度。

### 7.2 5.x 任意延时

- 消息属性 `__STARTDELIVERTIME__`；写入 TimerWheel/TimerLog。
- 时间轮按秒/槽位；到期批量扫描；精度 1s。
- 上限 24h（RocketMQ 5.x）；MQ-rust 可配。

### 7.3 MQ-rust 实现

```rust
pub struct DelayService {
    wheel: TimingWheel,
    log: DelayLog,       // 持久化到期时间 + 消息指针
    dispatcher: Sender<DueMessage>,
}
```

- 写入时先落 DelayLog，再插时间轮；重启从 DelayLog 重建。
- 到期投递到真实 Topic（写 CommitLog），再删除 DelayLog 条目。
- 水位/容量限制；超限拒绝或降级为普通消息（可配）。

## 8. 顺序消息

- Producer：按 sharding key 选 queue（`hash(key) % queue_count`）。
- Broker：同 queue 顺序 append；消费时对 queue 加锁（`QueueLockManager`）。
- Consumer：顺序消费，失败时挂起该 queue，按退避重试；不能跳过。
- Rebalance：queue 锁随消费者迁移；迁移期间阻塞该 queue。
- 边界：只保证同 queue；跨 queue 不保证。

## 9. 事务消息实现

### 9.1 模块

```text
mq-txn/
├── state.rs       # TxState, TxRecord, CAS
├── log.rs         # Tx WAL append/read/snapshot
├── scheduler.rs   # 分片时间轮 + 回查
├── coordinator.rs # 状态迁移 + 物化协调
├── reconcile.rs   # 对账
└── raft.rs        # openraft 集成
```

### 9.2 发送 Half

- `SendMessageProcessor` 检测 `sysFlag` 的 transaction 位。
- 调用 `txn.prepare(msg)`：写 Half + `TxRecord(Prepared)`（同批）。
- 返回 `SEND_OK` + `transactionId` + `halfOffset`。

### 9.3 Commit/Rollback

- `EndTransactionProcessor` 解析 `EndTransactionRequestHeader`。
- `txn.commit(tx_id, half_offset)`：CAS `Prepared → Committing`，物化，CAS `Committing → Committed`。
- `txn.rollback(tx_id)`：CAS `Prepared → RolledBack`，写 Op。
- 重复请求：查状态，已决则返回成功。

### 9.4 回查

- `TxScheduler` 每个 tick 取到期 tx（按 shard）。
- 找 Producer Group 在线连接；发送 `CHECK_TRANSACTION_STATE`。
- 收到响应后调用 `txn.resolve(tx_id, state)`。
- 超时/未知：`check_count++`，`next_check_at = now + backoff`。
- 超过 `max_check`/`max_age`：`TimedOut` + 策略。

### 9.5 物化

```rust
async fn materialize(tx: &TxRecord) -> Result<u64> {
    if let Some(off) = dedup.get(&tx.tx_id)? { return Ok(off); }
    let msg = half_store.read(tx.half_offset, tx.half_size)?;
    let real = msg.into_real_message(tx.topic, tx.queue_id)
        .with_property("__MQ_RUST_TX_ID__", tx.tx_id);
    let off = commitlog.append(&real)?;
    dedup.put(tx.tx_id, off)?;
    Ok(off)
}
```

## 10. 复制与 HA

### 10.1 主从复制

```text
Master: append -> 写入 replicate log -> 发送给 Slave（批量）
Slave:  接收 -> append -> 返回 ack(offset)
Master: 更新 slave offset / ISR；SYNC_MASTER 等待 ack
```

- 复制通道独立于客户端连接；批量 + 压缩。
- Slave 落后超过阈值移出 ISR；追平后恢复。
- 切换：Controller 选主，发放 epoch；新 Master 从最大 committed offset 开始。
- 旧 Master fencing：Store 检查 epoch，拒绝旧写。

### 10.2 Controller

- openraft 状态机：Broker 注册、心跳、角色、epoch、ISR。
- Leader 负责选主/切换；Follower 转发。
- 与 NameServer 同步路由（Broker 注册时带角色/epoch）。

## 13. 错误处理

| 层 | 策略 |
|---|---|
| 协议 | 返回明确 ResponseCode + remark；不 panic |
| 存储 | 磁盘满/IO 错误 → 只读保护 + 告警 |
| 事务 | 状态机 CAS 失败 → 重新读取；不可重试 → 审计 |
| 复制 | 超时 → 降级/移出 ISR；不静默丢 |
| 网络 | 连接断开 → 清理挂起请求；客户端重连 |
| 任务 | 所有后台任务捕获 panic，重启并记录 |

**禁止**：在请求路径 `unwrap()`/`expect()`；用 `Result` + 明确错误码。

## 15. R1 实现范围（最小闭环）

- [ ] workspace + `mq-common`/`mq-protocol`/`mq-store`/`mq-broker`/`mq-namesrv`。
- [ ] Remoting codec + `SEND_MESSAGE`/`PULL_MESSAGE`/路由/心跳。
- [ ] CommitLog + ConsumeQueue + 启动恢复。
- [ ] 单机 NameServer + Broker（Local 模式）。
- [ ] Java 4.9.8 `DefaultMQProducer` 发送、`DefaultMQPullConsumer` 拉取。
- [ ] `/metrics` + 基础日志。
- [ ] 兼容性脚本 + R1 报告。

**不做**：事务、顺序、延时、DLQ、复制、gRPC、ACL（R2/R3/R4）。
