# 11 · 性能基准与容量规划

> 性能不是“跑一个数字”，而是**可复现的实验**。  
> 本文件定义 MQ-rust 的负载模型、指标、方法、容量公式与调优清单；每轮把实测数据写入 `docs/rounds/Rxx.md` 并回填本文基线表。

---

## 1. 目标

| 场景 | 目标 | 说明 |
|---|---|---|
| 单机异步刷盘、单副本 | ≥ 20 万 TPS（1 KiB） | 开发机/普通 SSD 可能达不到，以性能机为准 |
| 单机同步刷盘、单副本 | ≥ 5 万 TPS | 组提交 |
| 3 副本同步复制 | ≥ 5 万 TPS，P99 < 20 ms | 同机/同 AZ |
| 3 副本异步复制 | ≥ 15 万 TPS，P99 < 30 ms | 允许秒级 RPO |
| 事务消息 | ≥ 普通消息 70% TPS | 同副本/同刷盘 |
| 消费 | ≥ 发送 TPS 的 80% | Push/Pull，批量 |
| 长尾 | P999 < 3×P99 | 排除 GC/磁盘抖动 |

> 这些是**工程目标**，不是对外 SLA；最终以性能机实测和 `10-测试与验收` 的 Gate 为准。

## 4. 指标与工具

### 4.1 指标

- **吞吐**：send TPS、consume TPS、bytes/s。
- **延迟**：P50/P99/P999/max（HdrHistogram）。
- **资源**：CPU、RSS、PageCache、磁盘 IOPS/带宽、网络。
- **错误**：失败率、超时、重试、DLQ。
- **积压**：consumer lag、dispatch lag、replica lag。
- **事务**：half/commit/rollback TPS、回查 QPS/延迟、未决数。

### 4.2 工具

| 工具 | 用途 |
|---|---|
| `tools/mq-bench`（Rust） | MQ-rust 原生压测；支持同步/异步/批量/事务 |
| RocketMQ `benchmark.Producer/Consumer` | Java 基线；同负载对比 |
| `criterion` | 微基准（编解码/存储/索引） |
| Prometheus + Grafana | 实时观测 |
| `perf`/`pprof` | CPU/内存火焰图 |
| `iostat`/`vmstat`/`ss` | 系统瓶颈 |

## 5. Java RocketMQ 4.9.8 基线（开发机 smoke）

> 条件：同机 loopback，1KiB，1 副本，`ASYNC_FLUSH`，`ASYNC_MASTER`，开发机 i5-4210M。  
> 结论仅用于“环境可用性/相对趋势”，**不作为 1.0 验收**。

| 场景 | 线程 | 消息数 | 结果 | 备注 |
|---|---|---|---|---|
| 同步发送 | 4 | 10,000 | **2,647 TPS**，平均 RT 1.507 ms，Max 355 ms，失败 0 | `benchmark.Producer`，1KiB，同机 |
| 同步发送（MQ-rust R2） | 4 | 2,000 | **1,261 TPS**，平均 RT 3.141 ms，Max 370 ms，失败 0 | debug + 二进制持久化，同机 |
| 异步发送 | 1 | 100,000 | **272 TPS**，发送 28,842，失败 19,631，平均 RT 3.8s | 单线程/在途与参数不匹配，判为无效基线 |

**分析**：
- 开发机只有 4 线程，Broker 与客户端/NameServer 同机，CPU 竞争严重；2,647 TPS 是“功能 smoke 级”数字，不代表 MQ-rust 目标。
- 异步基准出现大量失败与 3.8s RT，说明客户端在途/线程配置与服务端处理不匹配；不能作为性能结论。
- 需要在 Linux 性能机（16C/32G/NVMe）重跑，并使用固定线程/在途/批量。

## 6. 容量模型

### 6.1 存储

```text
消息体 = 日均消息数 × 平均大小 × 保留天数 × 副本数
索引   = 日均消息数 × 20B × 保留天数 × 副本数
事务   = 日均事务数 × (TxRecord 256B + Half 平均大小) × 保留天数
总容量 = (消息体 + 索引 + 事务) × (1 + 20% 余量)
```

示例：1 亿条/天、1KiB、7 天、3 副本：
- 消息体 ≈ 2.1 PB（未压缩）
- 索引 ≈ 42 GB
- 需按 Topic 冷热分层/压缩，不能全量 3 副本热存。

### 6.2 网络

```text
入向 = 峰值 TPS × 平均消息大小
复制 = 入向 × (副本数 - 1)
消费 = 峰值消费 TPS × 平均消息大小 × 下游组数
跨 AZ = 复制 + 消费跨 AZ 流量
```

### 6.3 磁盘 IOPS

```text
写 IOPS ≈ 峰值 TPS / 批量条数 × (1 + 刷盘放大)
读 IOPS ≈ 冷读 TPS / 批量条数
```

### 6.4 容量水位

| 水位 | 动作 |
|---|---|
| 70% | 告警，准备扩容 |
| 80% | 限流/清理冷数据 |
| 85% | 只读保护（可配） |
| 90% | 强制清理 + 拒绝写入 |

## 7. 调优清单

### 7.1 写入

- 批量发送/批量 append；组提交（`flush_interval` / `flush_bytes`）。
- CommitLog 文件大小 1GiB；预分配；mmap 预热。
- 避免在 async worker 做 fsync；独立 IO 线程。
- 锁分片：按 queue/segment 拆分 append 锁（保持顺序）。
- 关闭不必要的 CRC/属性校验（按场景）。

### 7.2 读取

- 批量拉取；长轮询；PageCache 预热。
- 冷读限流；避免全量回放打满缓存。
- 零拷贝（Linux `sendfile`）用于大消息。
- ConsumeQueue 预读；Index 仅按需构建。

### 7.3 复制

- 批量复制 + 压缩；流水线；独立连接。
- `min_isr` 与超时；避免慢 Slave 拖垮 Master。
- 跨 AZ 带宽预留。

### 7.4 事务

- 事务日志批量 append；TC 分片。
- 回查批量/退避/限流；避免风暴。
- 物化异步化（在语义允许时）。

### 7.5 运行时

- Tokio worker 数 = CPU 核数（或略少）；IO 线程独立。
- `mimalloc`（Linux）；对象池；`BytesMut` 复用。
- 避免全局锁；`DashMap`/分片。
- 监控 P99/P999，而不是只看平均。

---

## 8. 性能回归规则

- 每轮至少跑一次 smoke（即使功能轮）。
- 与上一轮/Java 基线对比；吞吐退化 > 10% 或 P99 退化 > 20% 必须解释。
- 性能优化必须附：假设、改动、测量、结论、回滚方案。
- 禁止用“单次跑分”作为结论；至少 3 次取中位数。
