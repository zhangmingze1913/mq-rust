### 2.2 JDK 17 兼容性修复

RocketMQ 4.9.8 的 `runserver.cmd` 默认使用 CMS GC，`runbroker.cmd` 使用 `-XX:-UseBiasedLocking`，在 JDK 17 上不可用。已修改：

| 文件 | 修改 |
|---|---|
| `bin/runserver.cmd` | 2g→512m；CMS→G1；移除旧 GC 日志参数 |
| `bin/runbroker.cmd` | 2g→1g；移除 `UseBiasedLocking`；旧 GC 日志→默认；DirectMemory 15g→2g |

> 生产环境建议使用 JDK 8/11 或按 RocketMQ 官方推荐版本；本次仅为本地验证。

### 3.6.3 已实现的关键逻辑

- Remoting 帧：`total_len = 4 + header_len + body_len`（不含自身 4 字节），支持半包/粘包、最大 64MiB 校验。
- `RemotingCommand`：JSON 字段 `code/language/version/opaque/flag/remark/extFields`，body 不序列化。
- CommitLog：`magic + len + crc32c + payload`，追加/按 offset 读/坏尾截断恢复。
- ConsumeQueue：20B 条目（offset/size/tagHash）追加与批量读。
- 事务状态机：`Prepared → Committing → Committed`、`Prepared → RolledBack`、超时/人工路径；非法迁移拒绝。

## 5. 问题与处理

| 问题 | 现象 | 处理 |
|---|---|---|
| 直连 GitHub/TLS 失败 | `schannel: failed to receive handshake` | 使用国内镜像 + `127.0.0.1:7897` 代理 |
| JDK 17 不兼容 CMS | `Unrecognized VM option UseConcMarkSweepGC` | 改 G1；移除 `UseBiasedLocking` |
| RocketMQ 默认 2g 堆 | 开发机内存压力 | 降到 512m/1g |
| 无 Docker/WSL | 无法容器化测试 | native harness 先跑；compose/K8s 清单交付，Linux/CI 补跑 |
| 异步 benchmark 参数异常 | threadCount=1、失败 19,631 | 判为无效；改用同步 4 线程 10k 做 smoke |
| PlantUML 中文 | 默认字体缺失 | `skinparam defaultFontName "Microsoft YaHei"` |
