## 2. Remoting 帧长度语义（关键）

文件：`remoting/src/main/java/org/apache/rocketmq/remoting/protocol/RemotingCommand.java`

`encodeHeader(int bodyLength)`：

```java
int length = 4;                 // header length field
length += headerData.length;    // JSON header
length += bodyLength;           // body
ByteBuffer result = ByteBuffer.allocate(4 + length - bodyLength);
result.putInt(length);          // <-- length field value
result.putInt(markProtocolType(headerData.length, ...));
result.put(headerData);
```

因此：

```text
length 字段值 = 4 + header_len + body_len
线上帧字节数 = 4 + length 字段值 = 8 + header_len + body_len
```

`decode(ByteBuf)`：

```java
int length = byteBuffer.readableBytes();   // 包含 4 字节长度字段
int oriHeaderLen = byteBuffer.readInt();
int headerLength = getHeaderLength(oriHeaderLen);
int bodyLength = length - 4 - headerLength;
```

**结论**：
- 我们最初把 `total_len` 写成 `8 + header + body` 是**错误**的；已修正为 `4 + header + body`，线上帧长度为 `4 + total_len`。
- `mq-protocol` 已加 `frame_length_excludes_its_own_field` 测试，防止回归。
- `02`/`08` 文档已同步说明。

**跨语言 golden**：`tools/java/FrameGolden.java` 用 4.9.8 `RemotingCommand` 生成 106 字节帧（length=102，header=95，body=3），`mq-protocol::decode_java_4_9_8_golden_frame` 已成功解码并校验 `code/opaque/language/body`。

```java
CheckTransactionStateRequestHeader header = new CheckTransactionStateRequestHeader();
```

具体字段名以 `CheckTransactionStateRequestHeader` 的 setter/JSON 序列化为准（R1 抓包补齐）。

## 4. 事务扫描

文件：`broker/src/main/java/org/apache/rocketmq/broker/transaction/queue/TransactionalMessageServiceImpl.java`

- 扫描 `RMQ_SYS_TRANS_HALF_TOPIC` 的 ConsumeQueue；
- 用 `RMQ_SYS_TRANS_OP_HALF_TOPIC` 的 op 记录判断已决；
- 对未决 half 发送回查；
- 超过 `transactionCheckMax` 丢弃并记录错误。

**结论**：MQ-rust 不照搬“全量扫描 Half Topic”，而是独立 Tx WAL + 分片时间轮；但协议行为要与 Java SDK 一致。
