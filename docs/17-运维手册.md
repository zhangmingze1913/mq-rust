# MQ-rust 运维手册

> 版本：0.9.0-rc.1 / 2026-11-25  
> 适用：Windows x64 原生部署；RocketMQ 4.9.8 客户端。

---

## 1. 端口

| 组件 | 默认端口 |
|---|---|
| NameServer | 9877 |
| NameServer Admin | 无（`--admin-listen`） |
| Broker | 10921 |
| Broker Admin | 9091 |
| Broker Metrics | 9090 |
| Broker Replica | `--replica-listen`（如 10931） |
| TC | 按 TC 配置 |

## 2. 启动

```powershell
mq-namesrv.exe --listen 127.0.0.1:9877 --cluster DefaultCluster `
  --broker-name broker-a --broker-addr 127.0.0.1:10921 --queues 8

mq-broker.exe --listen 127.0.0.1:10921 --namesrv 127.0.0.1:9877 `
  --queues 8 --store-root G:\MQ_soft\mq-rust-data\broker `
  --metrics-listen 127.0.0.1:9090 --admin-listen 127.0.0.1:9091
```

生产建议：固定 `store-root`、`audit-path`、`inbox-path`，避免相对路径。

## 3. 关键配置

| 参数 | 说明 |
|---|---|
| `--commitlog-shards` | CommitLog 分片数 |
| `--commitlog-segment-bytes` | 段大小，默认 256MiB |
| `--cq-segment-entries` | CQ 段条目数，默认 100000 |
| `--retain-messages/bytes/max-age-ms` | 保留上限，0=不限 |
| `--retain-interval-ms` | Retention 周期 |
| `--sync-replicate` | 同步复制 |
| `--replica-quorum` | 需要的 ack 数 |
| `--replica-timeout-ms` | 复制超时 |
| `--fence-url` | namesrv admin，旧主自动只读 |
| `--acl-file` | ACL JSON |
| `--admin-token` | Admin Bearer |
| `--trace-capacity` | 轨迹条数 |

## 4. 存储布局

```text
<store-root>/
  commitlog-0, .1, ... .meta
  half/, retry/, delay/, index/, offsets/
  cq/<topic>/<queue>.cq, .cq.1...
  retention.json
  fence_epoch
```

- `commitlog-*.meta`：首段全局 base，删除后不可丢；
- `retention.json`：队列 base_offset，必须与 CQ 同步；
- 删除任何 meta/retention 文件会导致偏移错乱。

## 5. 观测

```text
GET /health       -> ok
GET /stats        -> JSON（messages/commitlog_bytes/read_only）
GET /metrics      -> Prometheus
GET /trace/{id}   -> send/pull/tx/dlq
```

重点告警：

| 指标 | 说明 |
|---|---|
| `mq_broker_commitlog_bytes` | 磁盘增长 |
| `mq_broker_tx_pending` | 悬挂 half |
| `mq_broker_tx_timeout_total` | 超时回滚 |
| `mq_broker_pull_empty_total` | 空拉 |
| `mq_broker_send_total` | 发送量 |

## 6. 保留与回收

```text
--retain-messages 500 --retain-interval-ms 1000
--commitlog-segment-bytes 67108864
```

- 对齐段：直接删除 CQ 段；
- 非对齐：CQ 自身重写；
- CommitLog 删除整段，最后一段保留；
- 段大小越小，回收越精确，但文件更多。

## 7. 主从与故障切换

```text
master: --sync-replicate --replica-quorum 2 --replica-listen 10931
slave1: --replica-of <master>:10931 --advertise-addr <slave1>:10922 --promote-to <ns-admin>
slave2: --replica-of <master>:10931
```

- master 断连后 slave1 自动 POST namesrv admin，route epoch+1；
- 旧 master 重启加 `--fence-url <ns-admin>`，发现 route 不符即 `read_only=true`；
- 提升后 slave2 不自动追平，需要重建/重放；
- quorum 未满足时发送返回失败，客户端按 msgId 去重重试。

## 8. ACL

```json
{
  "accounts": [
    {
      "accessKey": "key",
      "secretKey": "secret",
      "whiteRemoteAddress": "10.0.0.0/8",
      "permissions": [{ "topic": "MQ_*", "perm": "WRITE" }]
    }
  ]
}
```

- `perm`: READ/WRITE/DENY；
- 热更新 `--acl-reload-ms`；
- Admin `/fence` 受 `--admin-token` 保护。

## 9. 故障排查

| 现象 | 排查 |
|---|---|
| 启动报 exe 被占用 | 停止旧 `mq-broker.exe` 后重建 |
| `replica ack timeout` | 检查 slave、`--replica-quorum`、网络 |
| CQ 修复日志 | 非对齐 retention 已改为重写，频繁出现需查盘 |
| 消费 offset 不对 | 检查 `retention.json` 与 CQ 一致性 |
| SQL92 Pull 报版本低 | 等首次心跳后再 pull（Push 正常） |
| 磁盘持续增长 | 配置 retention 与段大小 |

## 10. 已知限制

- 未达 5 万 TPS；
- 无容器实测；
- 无 Raft 选举；
- 无 TLS/gRPC/group ACL；
- 轨迹内存态。
