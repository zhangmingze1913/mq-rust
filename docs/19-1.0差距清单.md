## 2. 性能差距

```text
目标 50,000 TPS
MQ-rust 1M（retention 500）：8,438
MQ-rust 1M（无 retention）：4,481（优化后），无优化 4,073/32 失败
原生 RocketMQ 4.9.8 同机 1M：15,465
批量 64：24,982
消费：11,130
```

原生基线证明：该 2 核/4 线程 + HDD 机器上限约 15.5k，**50k 需更换硬件/集群**，不是纯实现问题。

瓶颈：

- HDD 随机/顺序写；
- 单 CommitLog 写锁；
- 请求级 fsync/flush；
- 单机 4 核。

建议：

1. NVMe SSD；
2. 按队列批量聚合 + 组提交（真正批量写）；
3. 多 CommitLog 分片 + 无锁队列；
4. 生产端 batch 128–512；
5. 独立消费/存储节点。

## 3. HA 差距

已有：

- 同步复制 + quorum；
- 从节点自动提升；
- namesrv route epoch；
- 旧主 fence `read_only`。

缺：

- Raft 任期/投票/日志复制；
- 脑裂自动仲裁；
- 落后副本自动追平；
- 事务状态跨副本迁移。

## 4. 容器差距

- 无运行时；
- Dockerfile/compose/K8s 仅静态；
- 未验证镜像、健康检查、PVC、Service。

## 5. 安全差距

- 无 TLS/mTLS；
- 无 gRPC；
- ACL 无 group；
- Admin token 仅 Bearer。

## 6. 结论

```text
功能/SDK 兼容：RC
性能/容器/严格 HA/安全：未达 1.0
=> 不满足生产 1.0
```

达到 1.0 的建议顺序：

1. SSD + 批量流水线冲 5 万；
2. 容器环境完成 compose/K8s 验收；
3. Raft 选举替代“先到先得”；
4. TLS/gRPC/group ACL；
5. 轨迹持久化与精确回收。
