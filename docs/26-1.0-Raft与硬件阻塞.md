# MQ-rust 1.0：Raft 现状与硬件阻塞

> 版本：R191 / 2026-11-26  
> 结论：Raft 消息日志主路径已实现并通过故障测试；5 万 TPS 与剩余生产化项仍受硬件/排期限制。

---

## 1. Raft 已实现

- 3 节点 openraft 消息日志（R175）；
- broker SEND/Pull（R176）；
- 三 broker 选主/切换（R177）；
- leader 自动发布 namesrv 路由（R178）；
- BATCH 单条日志（R186）；
- 延时消息复制，三副本一致（R187/R188）；
- 事务 half/commit/rollback 复制，三副本一致（R190/R191）；
- DiskLogStore：append-only JSONL，vote/term/log 持久化（R181）；
- follower 重启追平（R180）；
- 全集群重启恢复（R182）；
- 多数派丢失写入失败/恢复（R183）；
- K8s Pod netns 真正分区（R184）。

## 2. 性能

```text
非 Raft batch256   37,095 msg/s（验收值）
Raft batch256       1,929 msg/s
Raft 单条            未测（预计更低）
```

Raft 同步提交路径无法达到 5 万；非 Raft 路径在现有 2C/4T + HDD 上也无法达到 5 万。

## 3. 仍未完成

- Raft 分段日志/快照/压缩（当前全量 JSONL + 内存日志）；
- leader 崩溃时事务恢复/check-back 与 Raft 的完整交互；
- 真正的 5 万 TPS：需要 ≥8 核/NVMe 或 2–4 broker 集群；
- 完整 1M 长跑压测。
