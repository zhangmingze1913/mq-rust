## 3. 协议关键点

### 3.1 帧长度

```text
length 字段值 = 4 + header_len + body_len
线上帧字节数 = 4 + length 字段值
```

`header_len` 高 8 位是 serialize type：0=JSON，1=ROCKETMQ 二进制。RocketMQ `benchmark.Producer` 会设置 `SerializeType.ROCKETMQ`，因此必须支持二进制 header；普通 Java SDK 使用 JSON。

### 3.2 发送 Header

- V1 code 10：`producerGroup/topic/defaultTopic/defaultTopicQueueNums/queueId/sysFlag/bornTimestamp/flag/properties/reconsumeTimes/unitMode/batch/maxReconsumeTimes/bname`。
- V2 code 310：`a..n` 短名。
- 响应：`msgId`、`queueId`、`queueOffset`、`transactionId`。

### 3.3 拉取消息编码

按 `MessageDecoder.encode`：

```text
totalSize | magic | bodyCRC | queueId | flag | queueOffset | physicalOffset |
sysFlag | bornTimestamp | bornHost(4)+port(4) | storeTimestamp |
storeHost(4)+port(4) | reconsumeTimes | preparedTxOffset |
bodyLen+body | topicLen+topic | propertiesLen+properties
```

`properties` 使用 `\u0001` 分隔 key/value、`\u0002` 分隔键值对；缺少 `UNIQ_KEY` 时补齐。

## 5. 已知限制（R2/R3 处理）

| 限制 | 计划 |
|---|---|
| NameServer 静态单 Broker 路由 | R2 动态注册/心跳/多 Broker |
| Broker 仅内存索引 + JSON 持久化 | R2 接 `mq-store` CommitLog/ConsumeQueue 二进制格式 |
| 无 Push 消费/Rebalance | R2 `DefaultMQPushConsumer` |
| 无重试/DLQ/批量/Tag/SQL92 过滤 | R2 |
| 无事务/顺序/延时 | R3 |
| 无复制/Controller/TC Raft | R4 |
| 无 ACL/TLS | R4 |
| 吞吐仅 277 TPS（debug/JSON/开发机） | R2/R4 性能专项：release + 二进制 + 批量 + 组提交线程 |
