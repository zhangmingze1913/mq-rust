## 2. 关键根因：offsetMsgId 不是合法的 MessageId

事务客户端 `DefaultMQProducerImpl.endTransaction()` 第一步：

```java
MessageId id = MessageDecoder.decodeMessageId(sendResult.getOffsetMsgId());
```

`decodeMessageId` 按 **4 字节 IP + 4 字节 port + 8 字节 offset** 解析 16 字节（32 hex）的 ID。

我们最初把内部 `msg_id`（时间戳 + 序号）直接作为响应 `msgId`，导致：

```text
java.lang.IllegalArgumentException: port out of range:1133250317
    at DefaultMQProducerImpl.endTransaction(DefaultMQProducerImpl.java:1319)
```

`END_TRANSACTION` 在发网络请求前就抛异常，被 `sendMessageInTransaction` 的 try/catch 吞掉，因此 Broker 永远收不到。

### 修复

`SendMessageResponse.msgId` 改为合法的 offset message id：

```rust
fn offset_msg_id(port: u16, offset: u64) -> String {
    // 4-byte IPv4 + 4-byte port + 8-byte commitLog offset, hex encoded
    format!("7F000001{:08X}{:016X}", port, offset)
}
```

- `msgId` = 合法 offsetMsgId（Java 可解码）；
- `transactionId` = 内部 Half 键（用于 commit/rollback 查找）；
- 半消息 `commitLogOffset=0`，仍按 `transactionId` 命中 Half Store。

## 2.1 超时回滚（Half WAL）

发送一个 `UNKNOW` 事务消息，Broker 10s 后自动回滚：

```text
END_TRANSACTION ... commitOrRollback=0
transaction still unknown ...
expired half transactions rolled back expired=["7F000001470C070DEA4E7AC1279D0000"]
TX TIMEOUT RESULT visible=0
```

Half WAL：
- `half/` CommitLog 记录 `prepared/committed/rolled_back` 事件；
- Broker 重启后重放，未决 Half 继续参与超时扫描；
- 单测 `half_wal_survives_reopen_and_expires` 覆盖。

## 2.2 Check-back（code 39）

Producer 端：
- `executeLocalTransaction` 返回 `UNKNOW`；
- `checkLocalTransaction` 返回 `COMMIT_MESSAGE`。

Broker：
- Half 超过 3s 后，向注册的 Producer Group 发送 `CHECK_TRANSACTION_STATE`；
- Producer 回 `END_TRANSACTION(commit)`；
- Half 物化，消费者可见。

验证：

```text
TX CHECK RESULT checks=1 visible=1
```

Broker 日志：

```text
producer registered group="mq_rust_tx_check_producer_..."
check-back sent group="mq_rust_tx_check_producer_..." tx_id=...
END_TRANSACTION ... fromTransactionCheck=true ... commitOrRollback=8 ...
transaction commit ... committed=true
```

实现：
- `ProducerConnections` 按 group 保存连接写通道；
- `HEART_BEAT` 的 `producerDataSet` 注册 producer；
- 每秒扫描 `due_half(3000)`，构造 code 39 请求，body 为 Half 的 `StoredMessage::encode`。

## 2.4 事务状态 API 与回查上限

Broker 管理端口默认 `127.0.0.1:9091`：

```text
GET /tx
[{"tx_id":"7F...","topic":"MQ_RUST_TX_ADMIN","created_at_ms":...,"check_count":0,"age_ms":6202}]
```

参数：

```text
--admin-listen 127.0.0.1:9091
--tx-check-max 2
--tx-check-backoff-ms 1000
--tx-check-interval-ms 3000
```

- `check_count >= tx-check-max` 时自动回滚，避免无限回查；
- 每次回查后 `last_check_ms` 更新，按 backoff 再查；
- `tx_pending` 指标与 `/tx` 一致。

## 2.5 幂等生产

同一 `(topic, msgId)` 重复发送不会追加第二条：

```text
IDEM SEND 1 queueOffset=0
IDEM SEND 2 queueOffset=0
IDEM RESULT count=1
```

实现：`BrokerStore` 维护 `dedup: (topic, msg_id) -> StoredMessage`；`append` 命中直接返回已有消息，保证 send 重试不重复。

```text
--audit-path G:/MQ_soft/mq-rust-data/audit2.log
```

输出 JSONL：

```json

{"event":"tx.commit","msg_id":"...","operator":"broker","ts_ms":...,"tx_id":"..."}
```

## 2.7 人工 commit / rollback

Broker 管理端口新增运维接口：

```text
POST /tx/{txId}/commit
POST /tx/{txId}/rollback
```

验证：

```text
MANUAL txId=7F00000107B4070DEA4E7B45AF180000
MANUAL POST http://127.0.0.1:9091/tx/.../commit -> 200
MANUAL RESULT visible=1
```

用途：对账发现悬挂事务时，人工提交/回滚，审计写入 `tx.commit.admin` / `tx.rollback.admin`。
