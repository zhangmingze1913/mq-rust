# R205 · 快照阈值提高到 5 万条（消除长跑尾段超时）

> 日期：2026-11-26  
> 结果：快照由每 2000 条改为 50000 条；300s 三副本 516,608 条，仅 4 次超时。

---

## 1. 根因

R16 500s 尾段 140 次超时，发生在约 512k 消息（= 2000 个 batch256 日志）时：

- `LogsSinceLast(2000)` 触发快照；
- 快照序列化全部消息（约 50 万条）；
- apply 暂停，客户端 3s 超时。

## 2. 变更

```text
snapshot_policy: LogsSinceLast(2000) -> LogsSinceLast(50000)
max_in_snapshot_log_to_keep: 100 -> 1000
```

## 3. 结果

```text
3 副本 Raft，batch256，4 threads，300s
A/B/C messages = 516,608（完全一致）
Send Failed = 4（1024 条）
MPS 1477–1963
Max RT 2511ms
```

对比：

```text
R16 500s（快照 2000）: 513,024 / 140 失败
R17 300s（快照 50000）: 516,608 / 4 失败
```

## 4. 结论

- 快照暂停是长跑尾段超时主因；
- 提高阈值后 300s 仅 4 次超时；
- 快照仍会全量序列化，后续应改为增量/状态存储快照；
- 1M 长跑（>50000 日志）仍会触发一次快照，需要继续优化。
