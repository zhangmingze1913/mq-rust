# R230 · K8s 300s 长跑与控制面瓶颈

> 日期：2026-11-27  
> 结果：2Gi/3 broker 在 6GB Docker VM 下压测 300s 时控制面 TLS/EOF，无法取回数据；探针已放宽到 3s/5 次，内存回调到 1.5Gi。

---

## 1. 本轮尝试

```text
Docker VM 6GB / 3 CPU
broker limit 2Gi（3 副本）
liveness timeout 3s, failure 5
readiness timeout 3s, failure 5
300s batch256/4 threads
```

## 2. 现象

- 60s 内正常；
- 300s 中控制面 API 出现 `TLS handshake timeout`/`EOF`；
- 无法读取 perf pod 日志；
- 判断为 3×2Gi + namesrv + kind 超出 6GB VM，控制面被 OOM/挤压。

## 3. 调整

- broker 内存上限回调 `1536Mi`，requests `384Mi`；
- 探针保持 `timeoutSeconds: 3`、`failureThreshold: 5`；
- 复测需 Docker VM ≥8GB 或减少 broker 数。

## 4. 已有稳定证据

R229：60s 206,336 条、0 失败、0 重启（1Gi/6GB）。

## 5. 结论

- 300s 长跑尾段仍未取得有效数据；
- 5 万不可达；
- 控制面容量是当前 K8s 测试瓶颈。
